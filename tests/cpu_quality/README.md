# CPU/quality regression fixtures

Baseline: `8ca580d37cfc7823df7a62d40e13a0ae8e1b17b8`, JUCE 8.0.4. Full findings and limitations: [CPU report](../../docs/CPU-QUALITY-MODES-20261026.md). Tests return nonzero on failure in Release too. No fixed audio reference is regenerated by these tests.

## Native algebra / SIMD / stability

Configure the normal root CMake project (use `-DFETCHCONTENT_SOURCE_DIR_JUCE=/absolute/JUCE` for an existing checkout), then:

```sh
cmake --build build/compact-plugin --target quality_solver_auto quality_solver_sse2 quality_solver_scalar guitar_cuts_test --parallel 3
ctest --test-dir build/compact-plugin --output-on-failure
```

`solver_test.cpp` compares reduced port solutions with independent full Jacobians, checks ordered matrix products against scalar arithmetic, singular rejection, and nonpositive pentode screen voltage/FENV. Auto runtime dispatch, forced SSE2, and scalar are distinct executable targets. NEON and physical non-AVX/MSVC hardware were not tested.

## Actual processor tests

Use a separate build directory for each profile or explicitly set **all** cached switches when reusing one. System JUCE GUI/audio development dependencies are required even for a headless test.

```sh
cmake -S tests/ir_presets -B build/quality-audio -G Ninja \
  -DJUCE_SOURCE_DIR=/absolute/JUCE -DCMAKE_BUILD_TYPE=Release \
  -DIR_PRODUCT_SOURCE_DIR="$PWD/Source" -DIR_TEST_MAIN=quality_audio.cpp \
  -DIR_TRACE_CONVOLUTION=OFF -DIR_DISCARD_RIGHT_MUTATION=OFF
cmake --build build/quality-audio --parallel 3
ctest --test-dir build/quality-audio --output-on-failure
```

Entry point `quality_audio.cpp` accepts `pcm`, `modes`, `stress`, `metrics`. These have separate CTest entries. `pcm` creates two actual raw Float32 renders under the current working directory's existing `build/`; on the evidence run this was the repository root. There are 10240 mono samples per render at 48 kHz; PCM witnesses are not approved musical DI fixtures. `metrics` renders BEFORE_HIGH/HIGH/STANDARD/ECO and frozen 16×: spectral numbers are measurements, not a subjective quality gate. The inharmonic metric includes possible transient/noise residual and the 16× reference is not perfectly alias-free.

For all nine rate/quality combinations of true stereo PCM, use `-DIR_TEST_MAIN=stereo_quality_reference.cpp`. It compares R-only and distinct L/R input against two independent amp circuits plus a conventional integer FIFO, including each circuit's own zero-input settling. Neither positive energy alone nor an exact-zero assumption for a nonlinear idle circuit proves routing.

For a stronger R-only-to-MONO oracle, configure with `-DIR_TEST_MAIN=mono_reference.cpp`. It compares the full processor with an independently summed input feeding a single amp, gain ramps included, at three rates. Use `-DIR_DISCARD_RIGHT_MUTATION=ON` only in a **separate negative-test build**: all three comparisons must fail (exit 1). Mutation changes a build-local processor copy, never production. The default legacy `ir_presets_test.cpp` with `-DIR_TRACE_CONVOLUTION=OFF` exercises 131 checks; with trace ON, 132. Do not enable tracing for the alternative entry points.

Sanitizers: configure a separate `quality_audio.cpp` build with `-DIR_SANITIZER=thread` or `-DIR_SANITIZER=address,undefined`, trace OFF, then execute `modes` and `stress` with halt-on-error. The target instruments all linked JUCE translation units. Do not suppress race reports or use these timings for CPU acceptance.

Actual packaged Linux VST3: add `-DIR_BUILD_VST3_HOST=ON`, build the root VST3 and `compact_vst3_host`, then run:

```sh
build/quality-audio/compact_vst3_host_artefacts/Release/compact_vst3_host \
  "$PWD/build/compact-plugin/DjentyDonkey_artefacts/Release/VST3/Djenty Donkey.vst3"
```

This tests controller parameters, actual component state, non-default audio recall, R-only independence, wrapper bypass, and live mono/quality selection. Equality of mono amp outputs is isolated with downstream Cab/Cuts bypassed: mono duplication happens before stereo cabinet/filter histories. It does not require a stereo IR to become mono.

## Full-chain before/after CPU

Extract the full historical Source independently of the current working tree:

```sh
mkdir -p build/cpu-quality-baseline
git archive 8ca580d37cfc7823df7a62d40e13a0ae8e1b17b8 Source | tar -x -C build/cpu-quality-baseline
```

Configure two separate `tests/ir_presets` builds with `IR_TEST_MAIN=quality_bench.cpp`, trace/mutation OFF, identical Release compiler/flags/JUCE. Before uses `IR_PRODUCT_SOURCE_DIR=$PWD/build/cpu-quality-baseline/Source`, after uses `$PWD/Source`. Execute their `ir_presets_test` binaries sequentially without concurrent local loads. The baseline must report `version=before`; a current-source "baseline" is invalid.

Each execution prints `QUALITY_CPU` records and deliberately returns 1 if any strict deadline gate fails. Before: 48 configurations, after: 144 (extra qualities), each 160 measured blocks after 0.2 seconds warmup. Mono uses identical averaged inputs; stereo has distinct L/R signals. RED gain9/PrecisionDrive8/level7/master3, built-in cabinet/cuts ON, gates/noise OFF. Compare HIGH before/after by fs/lanes/block/pacing; never call reducing oversampling an equivalent-quality optimization. `p95`/`p99` use sorted indices151/158. Paced completion misses are separate from callback-duration overruns. Shared VM deadlines are evidence about that machine/run, not an ASIO guarantee.

`baseline/` contains only the 15 amp transitive headers at the pinned commit, with the namespace changed from `vamp` to `vamp_before`; original SHA-256 entries are in `SOURCE.txt`. Verify by reversing the namespace-only transform and comparing with `git show <pin>:Source/dsp/<name>`. `Reference16.h` additionally renames the AmpSim class to Reference16 and fixes the stages/cap to4 (16×). Do not change the baseline to match an implementation. Existing root Tone/Fault references and test bounds remain intact.
